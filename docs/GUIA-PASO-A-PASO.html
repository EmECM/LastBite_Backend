Cómo dejar todo funcionando en tu máquina

Siete pasos · una hora

Esto es lo que hicimos para que la base y la API funcionen. Seguí los pasos en orden. Si algo falla, al final está la lista de errores comunes.

01 Qué instalar 02 Los siete pasos 03 Orden de los archivos 04 Si algo falla 05 Lista de verificación
01 · Antes de empezar

Qué instalar

Cuatro programas. Todos gratis. Todos con instalador de Windows.

PostgreSQL 16 o 17
La base de datos. Durante la instalación te pide una contraseña: anotala, la vas a necesitar.
postgresql.org/download/windows
DBeaver Community
El programa para ver la base y correr los scripts.
dbeaver.io/download
.NET 8 SDK
Para compilar y correr la API. Tiene que ser la versión 8, no la 9.
dotnet.microsoft.com/download/dotnet/8.0
Git
Para bajar el código del repositorio.
git-scm.com/download/win

Cuando instales PostgreSQL, dejá todo por defecto. Puerto 5432, usuario postgres, y no desmarques nada. Lo único que tenés que decidir es la contraseña. Escribila en un papel.

02 · Manos a la obra

Los siete pasos

1

Conectar DBeaver a PostgreSQL

  1. Abrí DBeaver.
  2. Arriba a la izquierda, clic en el enchufe con el signo +.
  3. Elegí PostgreSQL y dale a Siguiente.
  4. Host localhost, Port 5432, Database postgres, Username postgres.
  5. En Password poné la contraseña que anotaste. Marcá Save password.
  6. Clic en Test Connection.

Listo cuando: dice «Connected» y aparece la conexión en el panel de la izquierda.

2

Activar «ver todas las bases»

Por defecto DBeaver esconde las bases. Sin esto no vas a ver la nuestra.

  1. Clic derecho en la conexión → Edit Connection.
  2. Pestaña PostgreSQL.
  3. Marcá Show all databases.
  4. OK. Después clic derecho en la conexión → Invalidate/Reconnect.

Listo cuando: al abrir la conexión ves varias bases y no solo una.

3

Crear la base de datos

Abrí un editor SQL con Ctrl + ] y escribí esto:

CREATE DATABASE lastbite;

Ejecutalo con Ctrl + Enter.

Listo cuando: refrescás con F5 y aparece lastbite en la lista de bases.

4

Correr los tres archivos SQL

Antes de cada uno, mirá arriba del editor. La base seleccionada tiene que decir lastbite. Si dice postgres, cambiala ahí mismo. Este es el error más común.

Abrí cada archivo con Archivo → Abrir y ejecutalo con Alt + X. Ojo: Alt + X, no Ctrl + Enter, porque son archivos con muchas sentencias.

  1. INSTALAR_TODO.sql — tarda unos segundos. Crea todo.
  2. S003__contrasenas_demo.sql — pone las contraseñas de prueba.
  3. T001__pruebas_reglas.sql — comprueba que todo quedó bien.

Listo cuando: el tercero muestra RESULTADO: 16 pruebas correctas, 0 fallas.
Ese mensaje sale en la pestaña Server Output, no en la de resultados.

5

Bajar el código de la API

Abrí PowerShell donde quieras guardar el proyecto y escribí:

git clone https://github.com/<usuario>/LastBite_Backend.git cd LastBite_Backend

Listo cuando: adentro ves la carpeta LastBite.Api y el archivo CONTEXTO-BACKEND.md.

6

Poner tu contraseña en la configuración

Abrí con cualquier editor de texto:

LastBite.Api/appsettings.Development.json

Buscá la línea que empieza con "LastBite" y cambiá solo la parte que dice Password= por tu contraseña de PostgreSQL. Lo demás queda igual.

"LastBite": "Host=localhost;Port=5432;Database=lastbite;Username=postgres;Password=TU_CONTRASEÑA"

Ojo: guardá el archivo. Es el paso que más se olvida.

7

Correr la API

cd LastBite.Api dotnet restore dotnet run

Se abre solo el navegador en Swagger. Si no, entrá a http://localhost:5080/swagger.

Probá estos dos, en orden. Se abren con «Try it out» y después «Execute»:

  • GET /api/ping → debe decir estado: ok
  • GET /api/ping/base → debe decir tablas: 30

Listo cuando: el segundo devuelve 30 tablas. Ahí ya tenés todo funcionando y podés empezar a programar.

Para probar desde el celular, la API se levanta distinto:

dotnet run --urls "http://0.0.0.0:5080"

Y hay que pasarle al equipo de frontend tu dirección de red, la que sale con ipconfig. El celular no puede usar localhost: eso apunta al propio celular. Los dos tienen que estar en el mismo wifi.

03 · Los archivos

Qué archivo hace qué, y en qué orden

Solo necesitás estos tres para la base. Están en la carpeta db del proyecto y también en docs dentro del repositorio del backend.

1º INSTALAR_TODO.sql Crea las 30 tablas, las vistas, los procedimientos, los triggers y los datos de prueba. Es un solo archivo que junta todo. obligatorio
2º S003__contrasenas_demo.sql Le pone contraseñas de verdad a los usuarios de prueba. Sin esto nadie puede iniciar sesión más adelante. obligatorio
3º T001__pruebas_reglas.sql Intenta romper la base a propósito, 16 veces. Sirve para comprobar que todo quedó bien instalado. No cambia nada. recomendado

Solo se corren una vez. Si volvés a ejecutar el primero, va a dar error porque las tablas ya existen. Si necesitás empezar de cero, borrá la base con DROP DATABASE lastbite; y volvé al paso 3.

Y estos son para leer, no para ejecutar

  • CONTEXTO-BACKEND.md — todo lo que necesitás saber para programar la API: estructura, nombres, los DTO y la lista de endpoints. Empezá por acá.
  • 12-mockups-completos.html — las 39 pantallas de la app, cada una con su endpoint y sus reglas.
  • 08-diccionario-datos-mvp.html — qué guarda cada tabla, columna por columna.
04 · Cuando algo sale mal

Si algo falla

Estos cinco errores nos pasaron de verdad. Son los mismos que te van a pasar a vos.

El error diceQué pasóQué hacer
password authentication failed for user "postgres" La contraseña está mal. En DBeaver: Edit Connection y escribila de nuevo. En la API: corregí appsettings.Development.json.
database "lastbite" already exists Ya la creaste, pero DBeaver la esconde. Volvé al paso 2 y marcá Show all databases.
syntax error at or near "" El archivo tiene una línea que solo entiende la terminal, no DBeaver. Ya está corregido. Si te sale, borrá la línea que empieza con \set y volvé a ejecutar.
relation ... does not exist Corriste el script sobre la base equivocada. Mirá arriba del editor: debe decir lastbite, no postgres.
tablas: 0 en /api/ping/base La API conecta, pero a una base vacía. Falta correr INSTALAR_TODO.sql, o lo corriste en otra base.
BASE_NO_DISPONIBLE al llamar la API La API no alcanza PostgreSQL. Revisá que el servicio de PostgreSQL esté corriendo y que la contraseña del appsettings sea la correcta.
401 en /api/zonas Nada. Es lo correcto. Ese endpoint pide token y el login todavía no existe. No es un error.

El truco que resuelve la mitad de los problemas: antes de ejecutar cualquier script, mirá la base que está seleccionada arriba del editor de DBeaver. Si dice postgres en vez de lastbite, todo lo que corras va a parar al lugar equivocado.

05 · Antes de decir «ya está»

Lista de verificación

Si podés marcar las seis, estás listo para programar.

DBeaver conecta y veo la base lastbite en la lista.
Adentro de lastbite veo nueve esquemas: core, seguridad, geo, comercio, oferta, venta, finanza, social y auditoria.
El archivo de pruebas dio 16 correctas, 0 fallas.
Puse mi contraseña en appsettings.Development.json y guardé.
dotnet run arranca sin errores y abre Swagger.
/api/ping/base devuelve 30 tablas.

Y ahora qué

Leé CONTEXTO-BACKEND.md completo. Ahí está tu módulo asignado, los endpoints que te tocan y cómo se llama cada clase que hay que escribir. Después abrí Cowork, seleccioná la carpeta del proyecto y usá los prompts de PROMPTS-PARA-EL-EQUIPO.md.

Ya está hecho: el proyecto, la configuración, las clases de Common, los ocho archivos de DTO y un endpoint completo de ejemplo (GET /api/zonas) que sirve de molde. Falta escribir los demás.
